# Kuji Desk v1.5.34 使用說明

## 第一次開啟

1. 使用 Windows，安裝並更新 Google Chrome。解壓分享包，執行 `KujiDesk.exe`。
2. 在平常的 Chrome 建立／開啟不同設定檔，分別手動登入一番賞。最多三個帳號；只使用一張卡片也可以。
3. 在要使用的 Chrome 設定檔開啟 `chrome://inspect/#remote-debugging`，啟用允許遠端偵錯的選項。若沒有此頁選項，先更新 Chrome；是否可用以該電腦實際顯示為準。
4. 每個設定檔先保留一個要交給助手的一番賞分頁。不要讓多張卡片綁定同一設定檔。
5. 在卡片按「連接 Chrome」。Chrome 出現「誰在使用 Chrome？」時開啟正確的設定檔；回總控的綁定視窗，從下拉清單明確選擇同一個名稱與目錄，按確認。
6. Chrome 要求允許遠端偵錯連線時，由本人按「允許」。連線最長等候 60 秒，依序完成各張卡片。
7. 用「切回視窗」核對 A／B／C 是否對應正確的網站帳號，必要時修改卡片名稱。

綁定會短暫開啟 Chrome 版本辨識頁並關閉；原網站頁保留。找不到設定檔時，先確認該設定檔有開啟的分頁。顯示已綁定其他卡片時，應選擇另一個設定檔，不要共用同一份登入。

## 設定與監看

- 貼上商品介紹頁或選箱列表網址。首頁也能作入口，但需本人選擇商品後才能取得 PID。
- 設定目標籤數、最短／最長秒數，按「儲存秒數／監看設定」。每輪會在區間內隨機等待。
- 按單一卡片或全部開始監看；開啟連線本身不等於開始監看。控制台若關閉，先按「開啟控制台」。
- 正常查箱使用目前分頁登入狀態發起 fetch，畫面不必整頁刷新；找到新滿箱後進入箱頁，依網站流程提交排隊一次。結果不明時先核對網站，不盲目重送。
- 「啟用入場重新整理功能」僅用於明確的暫時入場限制。原頁與四個助手頁各自隨機等待；通過後接續同商品，只保留一個成功頁。不要手動同時操作這些助手頁。
- 籤數與順位由目前網站資料解析，不是官方 JSON 庫存 API。沒有可辨識的箱子時顯示「—」。可按「更新全部籤數」或使用每三分鐘更新。
- 「箱子售完後自動找新箱」可控制售完後接續；空列表連續超過一小時會停止監看。
- 「執行紀錄」查看找箱、進箱、排隊與上一箱紀錄。

## Discord 與驗證提示

1. 按「DC Webhook 設定」，填入自己的 Discord Webhook。
2. 啟用 Discord，選擇通知事件、順位門檻及是否重複提醒，再儲存。
3. 「出現 Cloudflare 真人驗證時發送 DC 通知」與「彈出提示視窗」可獨立勾選。
4. DC 驗證通知預設開啟，本機彈窗預設關閉。彈窗不依賴 Discord，但必須保持桌面總控視窗開啟。同一次驗證各提示一次。
5. 遇驗證時請本人切回 Chrome 完成，再啟動監看。工具不處理驗證碼、不繞過驗證、不自動付款。
6. 不想接收「已通過入場限制」，取消對應勾選後儲存。分享包不會帶入作者的通知偏好與 Webhook。

儲存後通知設定立即生效，不需要中斷隊伍或重啟服務。

## 關閉、更新與分享

- 關閉桌面視窗、關閉控制台、停止監看與退出網站隊伍是不同操作。關閉桌面視窗不代表背景服務停止，也不等於退出隊伍。
- 現版接管本人已開啟的 Chrome。關閉助手服務只斷開連線，外部 Chrome 由本人管理；請自行確認網站隊伍。
- GUI F5 更新資料，不會載入新版 Python 程式。需要更換背景服務時，先等任務結束並核對隊伍。
- 一般獨立執行使用 `%LOCALAPPDATA%/KujiDesk` 保存設定與執行紀錄，或由 `KUJI_RUNTIME`／命令列明確指定。不要分享這些檔案。
- 對外只分享 EXE 與公開說明。不要附上 Runtime、Chrome User Data、Cookie、Webhook、panel-session 或個人執行紀錄。

## 驗證範圍

已完成本機語法檢查與打包、既有 Chrome 實際連接及查箱、設定畫面與 Discord 傳送驗證。尚未在另一台電腦驗證首次啟動；五分頁限制通過的完整流程及新 Cloudflare 通知／彈窗的實際驗證觸發仍待確認。網站改版、登入過期或連線授權被拒絕可能需要人工處理。
