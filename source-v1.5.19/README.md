# Kuji Desk 1.1 · 本機三帳號管理

不需擴充套件。用一個面板管理三個獨立 Chrome 專用視窗，帳號各自保存登入。

## 開啟

在目前工作空間雙擊 `work/kuji-manager/start.cmd`。會開啟本機總控面板，終端視窗請保持開啟。若面板已在執行，再次雙擊會回到既有面板。

第一次在其他電腦使用，需要 Python 3.11 以上與官方 Chrome；啟動檔會從 PyPI 安裝列在 `requirements.txt` 的依賴。這台電腦已完成依賴安裝。

## 第一次使用

1. 等原本瀏覽器中這次排隊／購買結束。不要同時用兩個環境操作同一帳號。
2. 在總控貼上選箱列表網址。張數預設 70，隨機等待預設 2.2–4.5 秒。
3. 對 A、B、C 分別按「開啟視窗／登入」。每個視窗手動登入不同帳號，不會讀取或匯入原本 Chrome／Edge／Brave 的 Cookie。
4. 若登入後回到首頁，在總控按該帳號「開啟選箱列表」。這個操作只在沒有進行中助手任務時可用，不會離開已辨識的排隊／購買頁。
5. 可編輯帳號名稱。確認三個帳號分配正確後，按各自「開始監看」或「一起開始監看」。一次開始只作用於已開啟、沒有進行中任務的帳號；每個帳號的失敗會分別顯示。
6. 在總控按一次「啟用／測試提醒音」。A、B、C 的音高不同；保留總控分頁以接收提醒。重新整理總控後需重新啟用聲音。
7. 發現新箱後，每帳號鎖定一箱，跳到詳情並觸發一次官方排隊按鈕。顯示個人順位才標記已確認。輪到時回到相應視窗手動繼續。

「停止全部監看」只停止仍在找箱的帳號，不會退出既有隊伍。「結束本次任務」只清除助手任務；先確認本次已完成或你已透過網站退出隊伍，再重新啟動。這不是退出網站隊伍的按鈕。

## 保存位置與更新

- 預設 `Runtime/kuji-manager/profiles/A`、`B`、`C` 保存三份瀏覽器登入資料。請勿分享或放到公開版本庫。
- `Runtime/kuji-manager/job-A.json` 等檔案保存任務與耗時；點按鈕前先寫入磁碟。程式意外中斷後會標示「需要確認」，不會自動重送。
- `Runtime/kuji-manager/panel-session.json` 是本機面板連線憑證，不是網站登入憑證。總控只監聽 `127.0.0.1:18766`，API 需此憑證。
- 更新只需修改本機程式檔，完成排隊後重新啟動。沒有擴充套件需要重新載入，也沒有接入網路自動下載更新服務。
- 在目前 checkout 使用 `Runtime/kuji-manager`。獨立解壓縮到其他資料夾時使用 `%LOCALAPPDATA%/KujiDesk`，之後更新程式仍沿用同一資料位置。若要搬移已登入的環境，使用環境變數 `KUJI_RUNTIME` 或 `manager.py --runtime 絕對路徑` 指向原資料位置，避免建立新設定檔。

## 監看與排隊流程

啟動先背景向伺服器取得最新列表，建立最大隱藏流水號的基準。之後每次隨機等待 2.2–4.5 秒，再用該專用視窗的登入狀態 GET 同一列表，解析 HTML。請求完成後才安排下一次，不並行轟炸。只看目前網址所指的列表頁，不掃描所有分頁。

新箱必須同時符合「流水號較大」與「張數完全相同」。同批多箱優先等待人數較少者。找到後先保存鎖定，進入詳情，驗證按鈕中的商品與箱子 ID，再保存提交紀錄並點官方按鈕一次。其後只被動讀取頁面 DOM／官方 WebSocket 通知，不自行傳送排隊 WebSocket 指令。

網站加入隊伍時可能自動重載，程式只重試讀取畫面，不重點加入按鈕。HTTP 錯誤、重新導向登入、無法解析列表會停止本帳號，交由人工確認。30 秒內未讀到個人順位則顯示待確認，仍可被動觀察之後出現的順位。監看新箱最長 30 分鐘，已進隊伍不受此找箱時限影響。

請勿在專用視窗另開同帳號的排隊分頁。程式不會關閉你額外開的分頁，也不會偵測其他電腦操作。電腦睡眠、網路中斷、網站調整、登入失效等仍會影響排隊。關閉終端／本機程式可能關閉專用視窗或中斷連線，請等排隊結束再關閉。沒有任何間隔能保證第一順位或避免網站限制。

## 1.1 退出重排與庫存面板

- 「離開本箱並重新監看」只作用於所選帳號。確認放棄順位後，按網站 `順番待ちを抜ける`，再確認 `はい`。必須讀回相同商品的選箱列表且不再有個人隊伍提示，才建立新基準重新監看新滿箱。結果不明就停止，不連續點擊退出或再排隊。
- 此操作會放棄原順位，且只找重新啟動後新開的滿箱，不立即排回舊箱。另兩個帳號不受單帳號重排操作影響。
- 修正實際網站 `あと54人であなたの番です` 的解析，顯示「前方還有54人」。與全箱總排隊人數分開，不推算為個人第54位。
- 庫存以頁面頂部「等賞一覧／残りくじ」摘要為優先來源，顯示各賞剩餘／原始數量。0 會顯示 0；未能讀取則顯示 —。Last One 未提供數量時不推算。
- 每秒讀取頁面上既有數值，不每秒向伺服器拉庫存。「更新籤數」沿用官方 `在庫情報を更新` 按鈕，遵守網站冷卻；不可按時停用。讀取時間代表本機讀到網站畫面的時間，不代表伺服器庫存更新時間。
- 升級後若保留上次任務紀錄，會先顯示需確認。開啟專用視窗後可被動讀回順位與庫存；不自動重送排隊。請完成網站狀態確認後，再結束助手任務或開始新監看。
