## 使用前先知道

Kuji Desk 是執行在你自己電腦上的 Windows 桌面工具，最多可同時連接三個你本人已登入的 Chrome 設定檔，用來監看新滿箱、依網站流程提交一次排隊，並顯示目前順位與剩餘籤數。

以下操作一定**由你本人處理**，工具不會代替你執行：
- 帳號登入與維持連線授權
- Cloudflare 真人驗證與其他安全驗證（工具不處理驗證碼，也不會繞過網站限制）
- 抽籤、購買確認與付款
- 自行決定是否退出網站隊伍（關閉 Kuji Desk 視窗不會替你退出隊伍）

## 第一次啟動與連接 Chrome

第一次使用時，建議**先完成一張帳號卡片，再綁下一張**，較容易確認每個視窗沒有對應錯帳號。

1. **準備環境**
   - 在 Windows 安裝並更新 Google Chrome。
   - 解壓分享包後，執行 `KujiDesk.exe`。
2. **用不同 Chrome 設定檔登入帳號**
   - 在你平常使用的 Chrome 開啟不同的設定檔（最多三個；只用一個也可以），各自**手動登入**一番賞。
   - 每個設定檔請先保留一個開啟中的一番賞分頁。不要讓多張帳號卡片共用同一個設定檔。
3. **開啟 Chrome 遠端偵錯**
   - 在要交給助手的 Chrome 設定檔網址列輸入 `chrome://inspect/#remote-debugging`，開啟允許遠端偵錯的選項。
   - 若頁面上沒有這個選項，請先更新 Chrome；是否可用以你電腦上的 Chrome 實際顯示為準。
4. **綁定到帳號卡片（A / B / C）**
   - 在 Kuji Desk 卡片上按「連接 Chrome」。
   - 若 Chrome 跳出「誰在使用 Chrome？」，先點選開啟你要綁定的設定檔。
   - 回到 Kuji Desk 跳出的綁定視窗，從下拉清單選擇**同一個**設定檔名稱與目錄，按「確認設定檔並綁定」。
   - 當 Chrome 詢問是否允許遠端偵錯連線時，由你本人按「允許」（連線最長等候 60 秒）。
   - 綁定過程中會短暫開啟並關閉一個 `chrome://version` 辨識頁，原本的網站分頁會保留。
5. **核對是否對應正確帳號**
   - 連線完成後，按卡片上的「切回視窗」，確認該 Chrome 視窗登入的是不是這張卡片對應的帳號。
   - 若需要標註辨識，可按「修改帳號名稱」調整顯示名稱。

> **常見狀況排除**
> - 下拉清單找不到設定檔，或連線失敗：先確認該 Chrome 設定檔目前至少有一個開啟中的分頁，並已開啟遠端偵錯。
> - 提示「已綁定其他卡片」：請改選另一個設定檔，不要多張卡片共用同一份登入。

## 設定商品與開始監看

完成 Chrome 綁定後（此時尚未開始監看），再設定商品與間隔：

1. **填入網址與條件**
   - 在上方貼上商品介紹頁或選箱列表網址。也可以先填網站首頁當入口，但必須由你先在該視窗選好商品、讓網址取得商品 ID 後，才會開始找箱。
   - 設定「目標籤數」（精確比對符合該籤數的新滿箱）、「最短秒數」與「最長秒數」。
   - 按「儲存秒數／監看設定」。每輪檢查會在最短與最長秒數之間隨機等待。
2. **確認服務狀態並開始**
   - 連接 Chrome 不等於開始監看。若頂部顯示控制台未開啟，先按「開啟控制台」。
   - 按單張卡片的「開始監看」，或按「一起開始監看」。

### 監看與排隊時會發生什麼事

- **一般查箱方式**：使用目前分頁的登入狀態在頁內發起同源 fetch 解析 HTML，不會整頁 F5，也不是官方 JSON 庫存 API。沒有可辨識的箱子時會顯示「—」。
- **找到新滿箱後**：依網站流程進入箱頁並提交排隊一次。若提交結果不明，工具不會盲目重送，請先由你查看「執行紀錄」與該 Chrome 視窗確認網站實際狀態。
- **箱子售完後自動找新箱**：勾選後，當箱子售完且網站返回同商品列表時可接續找新箱；若連續超過 1 小時沒有任何可辨識箱子，會自動停止監看。
- **啟用入場重新整理功能**：僅在網站出現明確的「暫時入場人數限制」頁面時使用。工具會以原頁加上 4 個助手頁（共 5 頁）各自隨機等待重整；開放進入同商品頁後，只保留一個成功頁並關閉其餘助手頁。進行期間請勿手動操作這些助手頁。
- **籤數更新與紀錄**：可按「更新全部籤數」，或勾選每 3 分鐘自動更新（介面目前字樣含「API」，實際仍是讀取頁面 HTML 解析，非官方庫存 API）。想看找箱、進箱、排隊與上一箱明細，可按右上角「執行紀錄」。

## Discord 通知與 Cloudflare 驗證提醒

1. 按主視窗上方的「🔔 DC Webhook 設定」。
2. 填入你自己的 Discord Webhook 網址（可按「📋 貼上」），建議先按「發送測試通知」確認送達。
3. 勾選「啟用 Discord 通知」，依需求選擇通知事件、前方等待人數門檻與重複間隔後，按「儲存設定」。
   - 儲存後會立即生效，不需要中斷隊伍或重啟背景服務。
   - 若不想收到進入商品頁／籤箱頁的通知，取消「通過入場限制…」勾選並儲存即可。分享包不會包含作者的 Webhook 與通知偏好。
4. **Cloudflare 真人驗證提醒**：
   - 「出現 Cloudflare 真人驗證時發送 DC 通知」（預設開啟）與「出現 Cloudflare 驗證時彈出提示視窗」（預設關閉）可分開勾選。
   - 本機彈窗不依賴 Discord，但必須保持 Kuji Desk 主視窗開啟才會出現；同一次驗證各自只提醒一次。
   - 遇到驗證時，工具會暫停自動監看並保留原視窗與隊伍資料。**請由你本人切回該帳號的 Chrome 視窗完成驗證**，確認畫面正常後再自行決定是否重新啟動監看。

## 關閉、重啟與對外分享注意

- **分清楚四個操作**：關閉 Kuji Desk 主視窗 ≠ 關閉控制台（背景服務） ≠ 停止監看 ≠ 退出網站隊伍。只關閉主視窗不會停止背景服務，也不會替你退出網站隊伍。
- **外部 Chrome 由你管理**：現版接管的是你原本開啟的 Chrome；關閉助手服務只會斷開連線，不會關掉你的 Chrome 或退出隊伍，請自行切回網站確認順位。
- **按 F5 只會更新畫面資料**：在主視窗按 `F5` 只會重新整理介面與讀取籤數，不會載入新版程式。需要「重新啟動服務」時，建議先等目前隊伍結束，並於重啟後自行核對網站狀態。
- **本機資料位置與隱私**：一般獨立執行時，設定與紀錄會保存在 `%LOCALAPPDATA%/KujiDesk`（或依 `KUJI_RUNTIME`／命令列指定位置）。對外分享時**只分享 `KujiDesk.exe` 與公開說明**，絕對不要附上 `Runtime` 資料夾、Chrome `User Data`、Cookie、Discord Webhook、`panel-session.json`、`cloudflare-popups.json` 或個人執行紀錄（`events-*.jsonl`）。
