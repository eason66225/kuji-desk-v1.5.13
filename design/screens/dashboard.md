# 主視窗與帳號卡

對照 `NativeUI.build`、`render`、`batch`、`drain`。共用 [設計 token](../tokens.md)。以下各區名稱為規格定位，UI 字串一律用佔位。

## 版面

視窗預設 1280×980，最小 1080×850。由上至下配置，左右留白 24。

| 區塊 | 位置與內容 |
|---|---|
| 原生 `tk.Menu` | 設定選單含通知設定、儲存監看設定及離開；工具選單含紀錄、F5、控制台開關及服務重啟。 |
| 頁首與連線列 | 頁首上 18、下 12。左為標題與副標佔位，右側由左至右為 Discord 設定、控制台開關、服務重啟、紀錄。下方連線列交代 UI 版本、服務狀態和 Discord 狀態。 |
| 監看設定 | 面板內距 16×12。上排四欄為網址、目標籤數、最短秒數、最長秒數，網址拿剩餘寬度，數字欄寬 8 個字元。下區左側三個監看勾選項，右側放批次停止／開始與手動更新籤數／儲存。 |
| 帳號卡 | A、B、C 等寬三欄，間距 10，外框 1，內距 14×12。卡內由上至下為帳號名稱、狀態、順位、目前箱號、補充說明、剩餘總數、賞別表、讀取標記、操作區。 |
| 底部訊息 | 10 pt、下距 14。顯示 `[TEXT: 本次操作結果、等待或部分帳號未更新的原因]`；長行可換行。 |

卡片操作以 2 欄×3 列排列：連接或切回／開始或停止監看；離開目前箱／重新查看；選擇設定檔／改名。賞別 `Treeview` 基準 10 列，每列 26 px；欄寬起點 95／115，第二欄置中，右側捲軸。只有表格取得卡片剩餘高度。提案：卡片補充說明依卡片實際內寬換行，含人工介入的資訊不得被固定三行裁掉。最小視窗優先壓縮表格可視列，保留操作區和讀取標記。較高 DPI 若頁首擠壓，將快捷動作移到標題下方；卡片長名稱與按鈕可換行。

## 資料與狀態

| 來源 | 呈現與行為 |
|---|---|
| 初次輪詢／服務關閉／讀取失敗（提案） | 連線列分別顯示 `[TEXT: 本機狀態讀取中]`、`[TEXT: 控制台已關閉與可用動作]`、`[TEXT: 本機狀態讀取失敗]`。相容版本 1.5.30 視為正常。舊版提示交代版本與重啟影響。 |
| 無帳號或僅登入模式 | 保留三卡位置。無帳號用未連接及資料空態；僅登入時依服務回傳可用動作。提案：輪詢暫失且曾有狀態時標明上次資料，停用依賴即時狀態的動作；真正沒有資料時清除畫面殘留值。 |
| 卡片 phase／note | `closed`、`idle` 顯示對應 phaseLabel；`opening`、`recovering`、`watching`、`submitting`、`leaving`、`waiting` 顯示階段及相關等待說明；`ready` 用亮綠＋就緒文字；`uncertain` 用橘色＋確認提示。驗證需求依來源辨識並顯示人工處理，勿把所有 `uncertain` 視為驗證。 |
| 順位／箱號 | 有順位顯示服務回傳數值（含 0），`ready` 用就緒佔位優先。未知用 `[TEXT: 尚無順位]`。箱號沿用當前網址箱 ID 優先、目標箱序號次之，缺值顯示 `—`。 |
| 庫存／賞別 | 有資料顯示剩餘總數與各賞別剩餘／原始。確認 0 用零值色和數字 0；未知用 `—` 且保持表頭。讀取標記要區分頁面讀取與獨立庫存更新，有時間才顯示時間。查詢失敗保留舊資料與時間，附 `[TEXT: 更新未成功並保留上次資料]`。 |
| 操作可用性 | 監看依 `canStart`／`canStop`，重新查看依 `canInspect`；連接／切回依 `opened`。離開目前箱沿用登入模式、階段限制和原生確認。帳號請求送出時沿用該卡 busy，提案同步顯示等待。批次更新以 `canRefresh`、適用 phase 與 busy 判定，零適用對象顯示原因。 |
| 快捷與關閉 | F5 更新介面與適用帳號庫存。關閉 Tk 視窗與關閉控制台服務的影響分別交代。涉及離開箱或服務停止／重啟時，確認框交代範圍，取消保留現況。 |

驗收情境：1080×850 仍可操作每張卡的最後一列；用 Tab 穿過頁首、設定、A→B→C 能辨識焦點；測樣同時呈現已知零、未知庫存、更新失敗與真人驗證提示，確認四者可辨識。
